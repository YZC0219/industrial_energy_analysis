# 指标字典

> **本文档的用途**：把本项目里每一个会出现在报告、SQL 结果表和论文里的指标，
> 逐条定义清楚 —— 它叫什么、怎么算、什么单位、什么口径、边界在哪。
>
> **为什么需要单独立一份**：同一个词在不同地方口径不同，是这类项目最容易出错的地方。
> 比如"综合能耗"在全厂口径和剔除公用工程口径下差 27.3%；"单耗"允许为 NULL 但**不允许为 0**。
> 这些判断散在代码注释里，读代码要读五处才能拼出一句完整定义。这份字典是它们的**唯一出处**。
>
> 核对日期：2026-09-20
> 复现方式：`python src/generate_data.py && python src/clean_data.py`
> 　　　　　`MYSQL_PWD=<口令> python src/import_mysql.py --init --run-analysis`
> 　　（本表所有"实测值"列都在上述管道跑完后从库中直查得到，可逐条复核）

## 0. 怎么用这份字典

三条约定，后面所有条目都遵守：

1. **每个指标只定义一次。** 若某个指标在多个查询里出现，字典给出**唯一定义处**
   （视图名 / 查询号），其余地方只能是它的引用，不允许重算。
2. **数值一律给出单位。** 本项目的单位混用情况严重（tce / kgce / t / kg / m³ / kWh / 元 / tCO2），
   去掉单位后同一列名可以差 1000 倍。所有列名都带单位后缀，这不是啰嗦，是防错。
3. **"口径"是不可省略的定语。** 说"综合能耗"必须说清是全厂还是剔除公用工程。

### 三种口径

| 口径代号 | 含义 | 用它的地方 |
|---|---|---|
| **全厂** | 含 W07 动力站（公用工程）| Q01 / Q03 / Q04 / Q05 / Q13 / Q14 / Q17 / Q18 / Q21 / Q22 / Q23 / Q28 / Q29 |
| **剔除公用工程** | `WHERE process_type <> '公用工程'` | Q02 / Q07 / Q08 / Q11 / Q12 / Q16 / Q20 / Q24 / Q25 / Q26 / Q27 |
| **仅连续型** | 再叠加 `is_continuous = 1` | Q11 / Q12 |

> **为什么全厂口径会重复计算**：W07 动力站烧天然气产蒸汽，蒸汽又被 W01/W02/W03/W05 消费。
> 蒸汽在 W07 侧算一次折标煤，在消费侧又算一次。所以**凡是涉及单耗的指标必须剔除 W07**。
>
> 实测：全厂 63,759.70 tce，剔除后 46,400.59 tce，比值 **72.77%** —— 即全厂口径把
> 27.23% 的能耗算了两遍。

## 1. 基础物理量（明细层）

这五个量是**唯一从事实表直接来的量**，其余所有指标都是它们的组合。

| 指标 | 定义 | 单位 | 来源 | 备注 |
|---|---|---|---|---|
| `consumption` | 某车间某日某能源品种的消耗量 | 随能源品种（kWh / m³ / t / kg）| `fact_energy_consumption.consumption` | 清洗后**不允许为 NULL**（插补兜底），不允许为负（取绝对值）|
| `output_qty` | 某车间某日的产量 | 随车间（吨 / 件 / 平方米 / 台 / 吨蒸汽）| `fact_production.output_qty` | **不允许插补** —— 它是单耗的分母，凭空补会直接污染核心指标；缺失即无记录 |
| `unit_price` | 结算单价 | 元/单位 | `fact_energy_consumption.unit_price` | ≤0 视为缺失并插补（按 能源×年月 中位数）|
| `cost` | 费用 | 元 | `fact_energy_consumption.cost` | **以 量×价 为权威**；与 量×价 偏差 >5% 即整列重算 |
| `avg_temperature` | 日均气温 | ℃ | `fact_energy_consumption.avg_temperature` | 全厂同一天同值；仅用于 Q11/Q12 相关性分析 |

### 派生量

| 指标 | 公式 | 单位 | 定义处 |
|---|---|---|---|
| `std_coal_kgce` | `consumption × std_coal_factor` | **kgce** | `v_energy_enriched` |
| `co2_kg` | `consumption × co2_factor` | **kgCO2** | `v_energy_enriched` |

**折标煤系数** `std_coal_factor`（kgce/单位）取 GB/T 2589-2020《综合能耗计算通则》**当量值**：

| 编码 | 能源 | 单位 | 折标煤系数 | 碳排放因子 | 参考单价 |
|---|---|---|---|---|---|
| E01 | 电力 | kWh | 0.1229 | 0.5703 | 0.6800 |
| E02 | 天然气 | m³ | 1.3300 | 2.1622 | 3.4500 |
| E03 | 蒸汽 | t | 95.7000 | 260.0000 | 220.0000 |
| E04 | 工业水 | m³ | 0.2429 | 0.3440 | 4.1000 |
| E05 | 压缩空气 | m³ | 0.0400 | **0.0000** | 0.2800 |
| E06 | 柴油 | kg | 1.4571 | 3.0959 | 7.8500 |

> **三个必须说清的边界**：
>
> 1. **用当量值，不用等价值。** 电力当量值 0.1229 kgce/kWh 是按热功当量折算；
>    等价值按发电煤耗折（约 0.32），两者差 2.6 倍。本项目全程用当量值，**不做换算**。
> 2. **压缩空气碳排因子为 0。** 它是二次能源（电驱动空压机产生），电力的碳排已经算过了，
>    再算一次就是重复计入。折标煤同理保留非零值（GB/T 2589 要求计入总能耗），
>    但碳排置零 —— 这两个口径不同是有意的。
> 3. **蒸汽的碳排因子 260 kgCO2/t 是"消费侧"口径**，用于 W01/W02/W03/W05 消费的蒸汽。
>    W07 生产蒸汽烧的天然气也在 W07 侧计了碳排，所以全厂口径下蒸汽碳排是重复的 ——
>    这也是单耗类分析必须剔除 W07 的原因之一。

## 2. 总量类指标

### 2.1 综合能耗

| 项 | 内容 |
|---|---|
| **定义** | `SUM(std_coal_kgce) / 1000` |
| **单位** | **tce**（吨标准煤）|
| **定义处** | `v_daily_workshop`（车间×日）、`v_monthly_workshop`（车间×月）；明细级在 `v_energy_enriched` |
| **口径** | 取决于查询：全厂 / 剔除公用工程 |

**为什么除 1000**：折标煤系数给的是 kgce，业务上习惯用 tce。**除以 1000 这一步是本项目
最容易漏的换算** —— 漏掉后 63,759.70 tce 会变成 63,759,700 kgce，数量级一眼能看出，
但如果只对比两个都漏了的数就发现不了。所以列名一律带 `_tce` 后缀。

实测值：

| 口径 | 综合能耗 | 费用 | 碳排放 |
|---|---|---|---|
| **全厂** | **63,759.70 tce** | 215,364,002.57 元 | 156,783.57 tCO2 |
| **剔除公用工程** | **46,400.59 tce** | 165,100,997.75 元 | 126,072.39 tCO2 |
| 比值 | 72.77% | 76.66% | 80.41% |

### 2.2 碳排放

| 项 | 内容 |
|---|---|
| **定义** | `SUM(co2_kg) / 1000` |
| **单位** | **tCO2** |
| **定义处** | `v_daily_workshop`、`v_energy_enriched` |
| **边界** | 压缩空气因子为 0（见 §1 说明）|

### 2.3 能源费用

| 项 | 内容 |
|---|---|
| **定义** | `SUM(cost)` |
| **单位** | **元** |

> **注意费用不是可加量之外的独立口径**：`cost` 在事实表里是 DECIMAL，求和精确，
> 但它是"实际结算价 × 量"，与"参考单价 × 量"不同。Q19 专门监控这个偏离。

### 2.4 日均能耗 / 日均费用

| 项 | 内容 |
|---|---|
| **定义** | `SUM(...) / COUNT(DISTINCT record_date)` |
| **单位** | tce / 天、元 / 天 |
| **定义处** | Q01、Q14、Q15 |

> **为什么是 `COUNT(DISTINCT record_date)` 而不是 `COUNT(*)`**：明细表一天有多行

## 3. 强度类指标（单耗）

**这是本项目最重要也最容易被误解的一类指标。**

### 3.1 单位产品综合能耗（单耗）

| 项 | 内容 |
|---|---|
| **定义** | `SUM(tce) × 1000 / SUM(output_qty)` |
| **单位** | **kgce / 产量单位** |
| **定义处** | 月度：`v_monthly_workshop.unit_energy_kgce`；日度：Q16 / Q24 / Q25 / Q28 各自 CTE 内 |
| **口径** | **一律剔除公用工程** |

**三个必须记住的性质**：

1. **×1000 是从 tce 回到 kgce。** 分子 `SUM(tce)` 是吨标煤，除以产量前要乘回 1000，
   否则得到的数会小 1000 倍。这跟 §2.1 的 `/1000` 是一对反向换算，**两处都容易漏**。
2. **单耗允许为 NULL，但绝不允许为 0。** 产量为 0 或无产量记录时，单耗置 NULL 而不是 0。
   若按 0 处理，前端那些天的单耗会被算成**无穷大**（除以 0），图上会出现一根冲天的线。
   Q28 用 `NULLIF(MAX(p.output_qty), 0)` 保证这一点。
3. **单耗不可加。** 两个车间的单耗加起来没有意义，必须先加各自的分子分母再相除。
   这就是 Q28/Q29 传"可加量"而不是"算好的比率"的原因（详见 §6）。

**分子/分母的层级必须一致**：月度单耗用月度的 `SUM(tce) / SUM(产量)`，不是"每日单耗取平均"。
两者不等价 —— 产量高的日子权重大，算术平均会高估。

实测（2024 → 2025 年环比，Q08）：

| 车间 | 2024 单耗 | 2025 单耗 | 同比 |
|---|---|---|---|
| 熔炼 W01 | 17.48804 | 16.82522 | −3.79% |
| 轧制 W02 | 13.39114 | 13.07453 | −2.36% |
| 热处理 W03 | 62.09224 | 60.05569 | −3.28% |
| 机加工 W04 | 0.21815 | 0.21234 | −2.66% |
| 表面处理 W05 | 0.25501 | 0.24859 | −2.52% |
| 装配 W06 | 3.40107 | 3.29734 | −3.05% |
| 包装 W08 | 0.03926 | 0.03824 | −2.59% |

> **七个车间全部为负**，落在 −2.36% ~ −3.79%。数据生成时设定的"单耗年降 3%"得到验证。
> 注意 7 个车间的单耗跨三个数量级（包装 0.039 vs 热处理 62.09），所以报告里画图必须按车间切换，
> 不能画在同一根 Y 轴上。

### 3.2 单位产品电耗

| 项 | 内容 |
|---|---|
| **定义** | `SUM(E01 的 consumption) / SUM(output_qty)` |
| **单位** | **kWh / 产量单位** |
| **定义处** | Q20 |
| **口径** | 剔除公用工程 |
| **与 3.1 的区别** | 分子只取电力，不是全部能源折算 |

### 3.3 碳排放强度

| 项 | 内容 |
|---|---|
| **定义** | `SUM(co2_kg) / SUM(std_coal_kgce)` |
| **单位** | **tCO2/每 tce** |
| **定义处** | Q21 |

**这个指标衡量的是能源结构清洁化程度，不是排放总量。** 它只跟"烧的是什么"有关，
跟"烧了多少"无关。实测夏季最高 **2.72**（2025-07）、冬季最低 **2.31**（2024-02）
—— 夏季天然气占比低、电力占比高，单位能耗更"脏"。

> 注意分子分母都是 kg 级，**没有除 1000**。所以它的值在 2~3 之间，不是 0.002~0.003。
> 这与 §2.2 的 `tCO2` 口径不同，列名必须区分。

### 3.4 能源费用强度

| 项 | 内容 |
|---|---|

| **单位** | **元 / 产量单位** |
| **定义处** | `v_monthly_workshop.unit_cost_yuan` |

## 4. 结构类指标

### 4.1 占比（折标煤口径 / 费用口径）

| 项 | 内容 |
|---|---|
| **定义** | `100 × 该分组的值 / 全部分组的值之和` |
| **单位** | **%** |
| **定义处** | Q03（车间占比）、Q04（能源品种占比）、Q10 |
| **实现** | `100 * SUM(x) / SUM(SUM(x)) OVER ()` —— 窗口函数，不用子查询 |

**同一批数据在两把尺子下的排序会打架，差异本身就是结论**：

| 能源品种 | 折标煤占比 | 费用占比 | 差 |
|---|---|---|---|
| 天然气 E02 | **64.09%** | 49.24% | 折标煤高 14.85pp |
| 电力 E01 | 24.18% | **39.61%** | 费用高 15.43pp |
| 蒸汽 E03 | 10.36% | 7.06% | |
| 压缩空气 E05 | 0.57% | 1.19% | |
| 工业水 E04 | 0.49% | 2.43% | |
| 柴油 E06 | 0.30% | 0.48% | |

> **读法**：折标煤口径告诉你"能耗压力在哪"（天然气），费用口径告诉你"钱花在哪"（电力和天然气）。
> 电力的费用占比远高于折标煤占比 —— 电贵，这是节能改造的重点方向。

### 4.2 待机损耗与待机占比

| 项 | 内容 |
|---|---|
| **待机能耗** | `SUM(CASE WHEN is_production_day = 0 THEN std_coal_kgce END) / 1000` |
| **待机占比** | `100 × 待机能耗 / 综合能耗` |
| **单位** | tce、% |
| **定义处** | Q13 |
| **口径** | 全厂 |

**停产日的定义**：`is_production_day = 0`，即源系统 `record_status = '停产'`。

> **这里有一个极易踩的坑**：停产日**不能**由"产量为 0"推出来。
> `fact_production` 对 8×731 个车间日**全都有记录且产量为正** —— 实测四个间歇型车间
> 各有 58 个停产日，但按"产量=0"数出来是 **0 天**。
> 停产日在源系统里是能耗明细表上的一个标志位（`record_status`），与产量表无关。
> Q28 专门把 `是否生产日` 原样带出来，就是为了让筛选后还能正确算待机损耗。

实测：四个间歇型车间各停产 58 天

| 车间 | 停产天数 | 待机能耗 | 待机占比 |
|---|---|---|---|
| 表面处理 W05 | 58 | 110.89 tce | 2.73% |
| 机加工 W04 | 58 | 34.10 tce | 2.12% |
| 装配 W06 | 58 | 19.82 tce | 1.91% |
| 包装 W08 | 58 | 8.46 tce | 1.87% |
| **合计** | | **173.27 tce**（折合能源费用 793,880.39 元）| |

> 四个连续型车间（W01/W02/W03/W07）停产天数为 **0** —— 它们全年不停产。
> 待机合计在全厂口径与剔除口径下**相同**（173.27 tce）：这四个车间本来就不含 W07，
> 而 W07 全年不停产，它的待机项本来就是 0。

### 4.3 日型（工作日 / 周末 / 法定节假日）

| 项 | 内容 |
|---|---|
| **定义** | `is_holiday=1 → 节假日`；否则 `is_weekend=1 → 周末`；否则 `工作日` |
| **优先级** | **节假日优先于周末** —— 国庆节里的周六算节假日，不算周末 |

实测：

| 日型 | 天数 | 日均能耗 | 日均费用 |
|---|---|---|---|
| 法定节假日 | 58 | 75.431 tce | 243,901.90 元 |
| 周末 | 187 | 82.573 tce | 274,582.57 元 |

## 5. 异常检测类指标

本项目有**三套互补的判据**，回答三个不同的问题。**混用会得到错误结论。**

| 方法 | 问的问题 | 判据形态 | 定义处 |
|---|---|---|---|
| 固定 2σ 阈值 | "今天 vs 该车间历史平均，是否异常？" | 逐日截面 | Q16、Q24 |
| 产量基线残差 | "今天 vs **同产量同季节**的期望值，是否异常？" | 逐日截面 | Q25 |
| CUSUM 累积和 | "最近一段时间是否**系统性偏离**？" | 累积 | Q27 |

> **关键区分**：前两个是**逐日**判据，每天重新比较；CUSUM 是**累积**判据，
> 它不看单日尖峰，只看持续性。若单耗持续偏低，每一天相对自己的邻域都可能"正常"，
> 前两种都检不出来 —— 只有累积起来才能发现。这正是 CUSUM 的用途。

### 5.1 固定阈值法（2σ）

| 指标 | 定义 | 单位 |
|---|---|---|
| `ue` | `tce × 1000 / output_qty` | kgce/产量单位 |
| `mu` / `sd` | 该车间 `ue` 的均值 / 样本标准差（`STDDEV_SAMP`）| kgce |
| `Z值` | `(ue − mu) / sd` | 无量纲 |
| **超限判据** | `ue > mu + 2*sd`（**单侧**）| — |

> **为什么是单侧**：单耗偏低是好事（节能），报出来是噪声。只报偏高。
> 但注意 Q24 的**控制图**画的是双侧 μ±2σ 带，图上会显示低于下界的点 ——
> 那是给眼睛看的，与"是否超限"这个布尔标记不是一回事。
>
> **样本量**：7 个车间 × 731 天 = **5,117** 个日点（产量>0 且剔除公用工程后）。

### 5.2 产量基线残差法

| 项 | 内容 |
|---|---|
| **模型** | `期望单耗 = a + b/产量 + g·sin(2π·年内第几天/365) + h·cos(…)` |
| **拟合** | 每车间独立，最小二乘**闭式解**（正规方程 `(X'X)β = X'y`）|
| **定义处** | `v_unit_energy_baseline` |
| **残差** | `r = ue − yhat` |
| **标准化** | `z_r = (r − mu_r) / sd_r` |
| **判据** | `r > mu_r + 2*sd_r` |

**为什么是 `1/产量` 而不是 `ln(产量)`**：单耗的生成机理是
`ue ∝ (待机底负荷 + (1−待机底负荷)·负荷) × 季节 × 趋势`，而负荷正比于产量，
所以 `ue = 待机底·k/产量 + (1−待机底)·k` —— 它本来就是 `1/产量` 的**线性**函数，
是精确形式，`ln(产量)` 只是近似。

**实测效果**（换用 1/产量 后残差 σ 的变化）：

| 车间类型 | 残差 σ 下降 |
|---|---|
| 连续型（熔炼/轧制/热处理）| 几乎无差（待机底负荷占比低，双曲线形态弱）|
| 间歇型（装配 1.657→1.012、机加工 0.196→0.140、表面处理 0.566→0.442）| **22% ~ 39%** |

**为什么带季节项**：天然气采暖、蒸汽冬季高，是**独立于产量**的第二部分结构。
不分离出来的话冬天的残差会整体偏正，**把整个冬季都报成异常**。

### 5.3 CUSUM 累积和

| 指标 | 定义 | 单位 |
|---|---|---|
| 递推式 | `S⁺ₜ = max(0, S⁺ₜ₋₁ + zₜ − k)`，`S⁻ₜ = max(0, S⁻ₜ₋₁ − zₜ − k)` | σ |
| **闭式解** | `S⁺ₜ = Cₜ − min_{0≤j≤t} Cⱼ`，其中 `Cₜ = Σ(zᵢ − k)` | σ |
| 松弛量 `k` | **0.5** | σ |
| 决策限 `h` | **9.9** | σ |
| 报警判据 | `GREATEST(s_hi, s_lo) > h` | — |
| 报警方向 | `s_hi > h → 偏高`；`s_lo > h → 偏低` | — |
| 定义处 | `v_unit_energy_cusum`（`h` 在 CTE `lim` 里写一次，随结果列带出）|

> **`h` 为什么是 9.9 而不是教科书的 5**：`h=5` 对应 `ARL₀ ≈ 300` 天，
> 那是为"在线连续监控、每天判一次"标定的。本项目是对 731 天历史做**一次性回顾**检验，
> 同一个门槛下误报率完全不同。
>
> 5000 次零假设仿真（纯白噪声，k=0.5）：
>
> | n | 中位 | 99 分位 | h=5 时的误报率 |
> |---|---|---|---|
> | 365 | 5.06 | 8.76 | 52.3% |
> | **730（本项目）** | **5.75** | **9.90** | **77.4%** |
> | 1461 | 6.45 | 10.40 | 95.6% |
>
> 即 n=730 时用 h=5，**77% 的车间会至少报一次警，全是噪声**。故按 99 分位取 9.9。
> 复现脚本：`python tools/calibrate_cusum_h.py`（容差 ±0.3，拦截"换数据长度后忘了重标"）。

**白化（whitening）是必须的**：CUSUM 前提是观测独立同分布，而单耗带强季节自相关。
必须减去「车间 × **自然月**」的残差均值再累积，否则"每年 2 月都偏高"这种**规律性偏移**
会被一路累积成持续漂移，误判成设备劣化。

> **为什么按"自然月"而不是"年+月"**：两年的同一个月本来就应该有同一个季节水平。
> 分成"2024-02"和"2025-02"两组会把**样本量砍半**（每组从 ~60 天降到 ~30 天），
> 而估计量越少越噪 —— 白化本身就是要减噪，结果反而引噪，得不偿失。
>
> 那**年际差异**怎么办？那属于**趋势**，正是 CUSUM 该抓的东西（单耗年降 3% 是渐变），
> 不该混进季节项里估掉 —— 否则真实劣化会被当成"又一年 2 月"给白掉。

实测效果（未白化最大 S → 白化最大 S）：

| 车间 | 未白化 S | 白化 S | 削减 |
|---|---|---|---|
| 熔炼 W01 | 37.19 | 11.00 | −70.4% |
| 轧制 W02 | 44.60 | 11.74 | −73.7% |
| 热处理 W03 | 39.03 | 10.26 | −73.7% |
| 机加工 W04 | 19.47 | 15.01 | −22.9% |
| **表面处理 W05** | 18.10 | **18.39** | **+1.6%（反而变差）** |
| 装配 W06 | 37.87 | 14.13 | −62.7% |
| **包装 W08** | 18.99 | **19.12** | **+0.7%（反而变差）** |

> **白化不是对所有车间都降噪，这是方法的适用边界，必须如实说明**：
> 间歇型车间的持续性本来就来自**节假日簇**而非季节，白化去掉的是**方差**而不是**信号**
> —— 按各自 σ 标准化后，累积和反而略升。
>
> 连续型车间的峰值掉到约三分之一（轧制 44.60→11.74），说明**那七成左右是季节伪影**。
> 两个最大 S 都按各自的 σ 标准化，所以它们的差**不是**一个可加减的分解，要结合车间类型读。

### 5.4 三法对比的辅助指标

| 指标 | 定义 | 出处 |
|---|---|---|
| `噪声压低比` | `残差σ / 原始σ`，即 `sd_r / sd_u` | Q26 |
| `报警段数` | `is_alarm` 由 0 变 1 的次数（`LAG` 实现）| Q26 |
| `固定阈值中基线不认_pct` | 固定阈值检出但基线不认的比例 | Q26 |
| `是否超限` | 布尔标记在 SQL 里算好，**前端不重复实现阈值逻辑** | Q24 |

> **`噪声压低比`的意义**：它量化"产量+季节模型解释掉了多少单耗波动"。
> 实测落在 **0.2465 ~ 0.7410**，即模型解释掉 **25% ~ 75%**。
> 包装车间 0.7410 最高（压低得最少），说明它的单耗波动主要不是产量和季节造成的。

## 6. 前端动态筛选的可加量口径

**这一节是 #14 动态筛选的数据契约，与前面所有口径都不同。**

筛选控件在浏览器里重算 KPI，因此后端**只能传可加的量**，不能传算好的比率。

| 数据源 | 粒度 | 行数 | 提供的量 | 定义处 |
|---|---|---|---|---|
| `D.ws_daily` | 车间 × 日 | 5,848 | 能耗 / 费用 / 碳排 / 产量 / 日型 / 是否生产日 | Q28 |
| `D.energy_daily` | 车间 × 日 × 能源 | 19,006 | 实物量 / 折标煤 / 费用 / 碳排 | Q29 |

### 6.1 为什么必须传可加量

全厂「费用 / 能耗」的月际比值（**元 / tce** 口径）在 **3,214 ~ 3,658** 之间摆动，
**极差 13.8%**，不是常数。

> 注意分母口径：这里除的是 **tce**（即 `std_coal_kgce / 1000`），得到的比值在 3,214~3,658。
> 若忘了 `/1000`，同一个比值会变成 3.21~3.66 —— **数值本身没错，但单位对不上**。
> 报告与 Q28 注释里用的是元/tce 口径，本字典保持一致。

| 方案 | 结果 |
|---|---|
| ❌ 后端算好"平均单价"，前端乘筛选后的能耗 | 筛选一动就全歪 |
| ✅ 后端传 费用 和 能耗 两个可加量，前端在同一行里相加再相除 | 比值自然对 |

前端**只做加法和除法**，所以后端要给可加的量。

### 6.2 对账恒等式（筛选引擎的自检）

这三个断言必须同时成立，`tools/verify_filter.mjs` 在 9 组筛选组合下逐一验证，
误差 ≤ 5e-3 tce：

```
sum(ws_daily.tce)                    == REPORT.totals.tce        （不加筛选时逐位相同）
sum(energy_daily.tce)                == sum(ws_daily.tce)        （两个立方体必须一致）
按车间/月/日型分组后再求和            == 对应的 KPI 卡
```

### 6.3 小数位数的约定

| 列 | 位数 | 为什么 |
|---|---|---|
| 能耗 / 碳排 | **6 位** | 前端要把 5,848 行加起来还原全厂口径。只留 4 位的话截断误差会累积到 0.07 tce —— 显示成两位小数就是 63,759.70 vs 63,759.63，**一眼能看出对不上** |
| 实物消耗量 | **6 位** | 同理，19,006 行累加。只留 2 位的话天然气会差到 0.1 m³ 量级 |
| 费用 | 2 位 | `cost` 是 DECIMAL，求和精确，两位足够 |
| 单耗 | 4 位 | 只用于显示，不参与累加 |

### 6.4 NULL 的语义

**`产量` 与 `单位产品能耗` 可以是 NULL，且 NULL ≠ 0。**

Q28 用 `LEFT JOIN fact_production` 取产量：车间当天可能没有产量记录，
那时产量为 NULL、单耗也为 NULL。前端遇到 NULL 就当"这天没有单耗口径"跳过，
**不当作 0 产值** —— 若按 0 处理，那些天的单耗会被算成无穷大。

> 这也是 Q28 行数从 5,117 涨到 **5,848** 的原因：`LEFT JOIN` 保留全部
> 8×731 = 5,848 个车间日，而不是只有产量>0 的 5,117 个。

| 为什么用 9.9σ 而不是 5σ？ | 零假设仿真 99 分位 | n=730 时 h=5 误报率 77.4% |

### 单位对照（防错用）

| 单位 | 数量级 | 出现处 |
|---|---|---|
| **kgce** | 千克标煤 | 明细级 `std_coal_kgce`、单耗分子 |
| **tce** | 吨标煤 = 1000 kgce | 所有汇总的"综合能耗" |
| **kg / tCO2** | 千克 / 吨碳排 | 明细级 `co2_kg` / 汇总 `tCO2` |
| **kgce/产量单位** | 单耗 | 分母随车间变化（吨/件/平方米/台）|
| **tCO2/每 tce** | 碳排强度 | 值域 2~3，**没有除 1000** |

> ⚠️ **分母单位随车间变**：熔炼的单耗是 kgce/**吨**，装配的是 kgce/**台**，
> 包装的是 kgce/**件**。**跨车间比较单耗是没有意义的**，只能各自和自己比。
> 报告里画图必须按车间切换，原因就在这。

## 8. 维护约定

改数据或改口径时，这份字典要跟着动的地方：

1. **改折标煤/碳排系数** → 更新 §1 的系数表，并重跑全部 29 份基线（`tests/update_baseline.py`），
   提交信息里写明为什么变。
2. **新增指标** → 先在字典里定义（含单位、口径、定义处），再写 SQL。**不允许先写 SQL 后补定义。**
3. **改 `h` 或 `k`** → 重跑 `tools/calibrate_cusum_h.py`，更新 §5.3 的仿真表。
4. **改 Q28/Q29 的小数位数** → 重跑 `tools/verify_filter.mjs`，确认 6.2 的三个恒等式仍成立。
5. **报告里的正文数字是手写死的**，改完数据后必须逐个核对（见 README 的更正横幅）。

> 这份字典与 `sql/create_table.sql`、`sql/analysis.sql` 的关系是：
> **字典说"是什么"，SQL 说"怎么算"。** 两者矛盾时，以 SQL 的实测输出为准，
> 并回来修正字典 —— 但要把这个矛盾记录下来，因为它通常意味着某处注释已过期。
