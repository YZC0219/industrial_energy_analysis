# 语义层消费迁移：HTML 报告与既有 API

2026-10-03 已将 HTML 报告的数据读取和既有 API 的分析产物读取接入 `governance/consumers.py`。该适配器按语义目录解析文件名，检查已提供的字段及数值，返回原有字符串数据契约；未知文件、未知字段及非有限数值均失败。历史消费者仍支持规范表的字段子集，而新表格指标 API 继续要求完整字段契约，两者不能混称同样严格的模式。

既有 `/api/v1/metrics` 的日期/车间筛选和求和使用统一适配器，并从 YAML 定义取综合能耗、费用、碳排放的源字段。若这些定义变为非可加或排除公用工程的口径，会拒绝沿用旧“全厂求和”接口，避免悄悄改变业务意义。保留原端点、返回字段、小数位及空范围零值。新的语义指标端点仍使用其原有空范围 null 规则。

HTML 报告中的 Q 查询读取已统一；原始质量、预测和工程证据文件仍按各自来源读取。没有覆盖现有 `output/report.html`，迁移验证使用新的 D 盘导出目录。

入口 `python tools/verify_semantic_consumers.py`。先用 `python tools/verify_semantic_runtime.py` 在本机现有 MySQL 创建 29 条分析的只读快照导出，再执行消费端验证。

- 完整 `make_report.build()` 数据与迁移前 CSV 读取实现生成的数据逐项一致，JSON 留在报告指定的 D 盘目录。
- 旧 API 的全厂、W01、2025-01/W02 三种范围与语义标量一致；全厂费用为 215,364,002.57 元。
- 原异常明细和报告摘要端点正常；29 个表格指标 API 与对应查询一致。
- 隔离 LocalExecutor 主 DAG 已用当前代码重新运行首次装载和相同输入重放，每轮 19 个任务全部 success，29 份查询 SHA-256 与仓库行数/费用一致，报告成功生成。为迁移新增的语义依赖已纳入源码哈希检查。
- 101 项相关回归通过，涵盖旧接口错误语义、日期与分页、报告证据边界、未知字段和共享汇总错误。

报告为 `output/extensions/semantic_consumers_runtime.json` 和更新后的 `output/extensions/pipeline_scheduler_runtime.json`。汇总在 `output/extensions/runtime_summary.json`；主 DAG 验收仍显式关闭 Hive/Spark、完整流批对账和深度模型分支，未切换原调度部署。

## 仍未迁移

Metabase 原 SQL 卡片、浏览器中的全部衍生公式和导入脚本发布协议尚未整体改用新语义入口。离线 HTML 的交互筛选仍在浏览器计算，其输入已来自统一查询契约，但这不等于所有前端算法已经集中到服务端。实际通知、权限认证、生产发布与实测收益仍需对应配置和数据。
