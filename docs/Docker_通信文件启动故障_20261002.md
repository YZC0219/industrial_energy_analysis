# Docker 通信文件启动故障（2026-10-02）

首次尝试时，Kafka 队列桥接实际验收受 Docker 启动失败阻断。后续继续工作时发现 Docker 引擎和原有服务已恢复，Kafka 桥接实际验收已通过，见 `output/extensions/kafka_outbox_runtime.json`。恢复原因未确认；不能归功于失败的备份重命名尝试。以下保留首次故障诊断记录。

后台日志的根错误为 `initializing Secrets Engine`，重命名 `engine.sock` 为 `engine.sock.stale` 时返回 `The file cannot be accessed by the system`。当前 Docker 引擎命名管道不存在，localhost:29092 拒绝连接。

检查到 `C:\Users\32074\AppData\Local\docker-secrets-engine` 只含一个 0 字节 `engine.sock`；父目录属性包括 Encrypted，文件属性包括 ReparsePoint 和 Encrypted。ACL 对当前用户与管理员授予 FullControl，因此不能只归因于普通 ACL 权限。

经用户明确授权，尝试原地备份重命名该通信目录；普通权限及提权执行均报 Access denied，随后 .NET Directory.Move 也失败。目录未成功移动，没有删除数据、调整 ACL、解密数据或执行 Docker 工厂重置。修复日志保存在 `D:\industrial_energy_analysis\tmp\docker-start\repair.log`。

Docker 官方问题库存在相同通信文件错误的用户报告，并记录父目录重命名的临时办法，但该办法在本机未成功：[docker/for-win #15064](https://github.com/docker/for-win/issues/15064)。本机加密属性与拒绝访问是否存在因果关系尚未验证。

`tools/verify_kafka_outbox_runtime.py` 已实现独立主题/消费组的真实验收：落盘后未提交 offset 即进程崩溃、重启重放去重、坏 JSON 阻断与再次启动不越过坏消息。已加入 TCP 预检查：运行时不可用会在创建主题前退出并提示恢复环境。首次检查时代码编译与 77 项回归通过，但实际 Kafka 验收因环境故障暂缓；恢复后的验收及 78 项回归现已通过。

复核时原目录仍带 Encrypted 属性，`cipher /c` 无法读取其密钥信息，但 Docker 已能运行，因此没有继续更改该目录。若故障复发，需在交互式管理员终端复核目录访问和 Windows EFS 状态，再选择具体修复办法。不要选择 Docker 的 Reset to factory defaults，它可能删除镜像和数据卷。任何涉及现有数据移动、解密或目录权限更改的后续方案都需要单独授权。
