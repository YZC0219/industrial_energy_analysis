> 基线数字。所有数字均由 `src/clean_data.py` 在固定种子（`20240918`）数据上
> 跑出，可用 `python src/generate_data.py && python src/clean_data.py` 复现。
>
> 核对日期：2026-09-20　对应版本：`v0.1` (`96e3974`)

## 3. 修正情况

| 修正原因 | 命中条数 | 处理方式 |
|---|---|---|
| 消耗量缺失 | 295 | 按 车间×能源×年月 中位数插补 |
| 单价缺失或为 0 | 266 | 按 能源×年月 中位数插补 |
| 费用 ≠ 量×价（偏差 >5%） | 229 | 以 量×价 重算 |
| 负消耗量（仪表倒走） | 45 | 取绝对值 |
| 单位写法归一 | 1,220 | 按能源主数据映射为标准单位 |
| 能源编码回填 | 383 | 由名称经别名表回填 |

**受修正影响的记录共 674 条**（占清洗后 3.55%）。

> **引用时注意**：上表六个数字**不可直接相加**。前四类是"记录级修正"，一行
> 可能同时命中多类；`clean_fixed.csv` 一行只记一个主因（`fix_reason`），
> 因此各主因条数之和（295+261+73+45=674）等于去重后的记录数，而非命中次数。
> 后两类（单位归一、编码回填）是**字段级**统计，在剔除前计算，与记录数不同量纲。
>
> 论文中若需表述总量，请用"**674 条记录被修正，另有 1,220 条记录的单位写法
> 与 383 条记录的能源编码经标准化处理**"，不要写成"共修正 2,438 条"。

修正明细逐条记录在 `output/clean_fixed.csv`（含 `fix_reason` 字段）。

## 4. 清洗后数据的质量约束

以下约束由 `tests/test_clean_data.py::TestCleanArtifacts` 自动验证，每次
`pytest` 都会检查：

| 约束 | 含义 |
|---|---|
| 业务键唯一 | `(日期, 车间, 能源)` 无重复 —— 否则装载时会被唯一键静默丢弃 |
| 消耗量非负 | 负值已取绝对值 |
| 消耗量无缺失 | 已按分组中位数插补 |
| 单价无缺失且 >0 | 单价是费用与折标煤口径的输入 |
| 费用 = 量×价（±5%） | 费用以量×价为准重算 |
| 单位与能源编码一致 | 已归一为 kWh / m³ / t / kg |
| 编码均在标准集合内 | 别名已映射干净 |
| `is_production_day` 与 `record_status` 自洽 | 停产日记录保留（Q13 待机损耗分析依赖） |

## 5. 管道可复现性

在固定种子下重跑 `generate_data.py` + `clean_data.py`，六份产物
（`clean_energy.csv` / `clean_production.csv` / `dim_calendar.csv` /
`clean_rejects.csv` / `clean_fixed.csv` / `raw_energy_data.csv`）与首次生成
**逐字节一致**。已验证（2026-09-20）。

这是 `tests/baseline/` 下 23 份查询结果快照能作为回归基线的前提。

## 6. 已知限制

1. **数据为模拟数据**。上述指标反映的是**注入脏数据后的清洗能力**，不能
   解释为真实企业的数据质量水平。论文中须明确说明这一点。
2. **插补方法为分组中位数**。未使用回归插补或多重插补。对消耗量这类强
   季节性指标，中位数插补会低估季节峰值处的缺失值。影响幅度未量化。
3. **离群判定阈值 3×IQR 为经验取值**。取 1.5 会把正常冬季高峰判为离群，
   取 3 只抓 8~15 倍的仪表故障级异常。该阈值的选择依据是数据注入方式，
   在真实数据上需重新标定。
