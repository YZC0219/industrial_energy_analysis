# 阶段五：能效基线与节能情景评估

## 当前交付

本阶段以独立的离线分析入口起步，读取 `output/clean_energy.csv` 和
`output/clean_production.csv`，产出车间年度能效基线、2024/2025 单耗对照，以及

阶段五同时纳入独立的真实数据验证：UCI 钢铁行业能耗数据（韩国单一钢厂、2018 年、
35,040 条 15 分钟记录）已保存在 `data/real/uci_steel_energy/`，来源、许可、抓取时间、
文件 SHA-256 和当时的 robots 判定记录在 `provenance.json`。2026-09-28 再次请求
`https://archive.ics.uci.edu/robots.txt`，站点返回 HTTP 404，即当前没有发布 robots 规则；
按既有下载脚本的保守策略，401/403 会停止，而 404/410 作为无规则处理。因为所需数据和
分析产物已在仓库，本次没有重复下载或覆盖文件。

真实数据的滚动预测入口是 `ml/uci_steel_experiment.py`，现有评估结果位于
`output/paper/uci_steel/uci_steel_experiment_summary.json`。按 7 个滚动折、共 210 个测试日，
LightGBM 的 MAE 为 **769.85 kWh/日**，7 日季节朴素基线为 **869.62 kWh/日**；本数据集上
LightGBM MAE 低约 **11.5%**。这是单厂单年的预测实验，不能外推为普遍模型优势或节能成效。

本轮新增设备无关的工况诊断入口 `tools/phase5_real_data_diagnosis.py`：以前 10 个月作为
基线，在相同负荷类别、工作日/周末类型和日内 15 分钟时段内计算经验 P95；仅对最后两个月
筛查，将高于 P95 的连续间隔合并为待核查事件，并建立低滞后功率因数复核队列。按时间切分
应用阈值，避免用评估期数据本身校准阈值。运行：

```powershell
python tools/phase5_real_data_diagnosis.py
# 可选：显式提供电价后才计算费用情景
python tools/phase5_real_data_diagnosis.py --tariff-yuan-per-kwh 0.8
```

默认报告和明细写入 `output/phase5_real_data/`，来源哈希、时间完整性、基线/评估时间窗、
阈值参数和边界写入 `provenance.json`。当前复跑对 5,856 条评估记录发现 **133 个候选
15 分钟间隔、合并为 62 个事件**；相对训练期匹配 P95 的候选超额量为 **1,361.73 kWh**。
10%/25%/50% 的降幅情景分别为 **136.17、340.43、680.87 kWh**；因未提供实际电价，
未估算费用。这些是供人工筛查和方案讨论的敏感性场景，绝非确认的浪费量、可实现节能量
或投资回报。

## 指标口径与解释限制

- 年度单耗：`年度折标煤 tce × 1000 / 年度产量`，单位为 `kgce/产量单位`。
- 比较仅在同一车间、同一产量单位内进行。W07 动力站被排除，避免公用工程生产与消费重复计量。
- 基线差额：`2024 年单耗 × 2025 年实际产量 / 1000 - 2025 年实际能耗`。它表示相对历史强度的算术差，不证明某项措施导致了节能。
- 能源情景把 2025 年该车间该能源的消耗、费用和碳排按同一比例缩减。输出是敏感性分析，不是现场实测、措施承诺、净收益或投资回报。
- 能源系数与碳因子沿用 [指标字典](指标字典.md) 和 `sql/create_table.sql` 中的项目口径；输入缺少必需字段、出现未知编码、重复业务键或关键数值缺失时，脚本会停止。
- 当前源数据是项目模拟数据，适合演示计算流程，不可作为真实工厂节能承诺或审计凭证。
- UCI 数据只有用电、功率因数、无功功率、时间和负荷类别，没有产品产量、工序/设备映射、能源价格或改造事件；因此适合验证负荷预测与数据处理，不可计算单位产品能耗、节能收益或措施因果效果。
- ITAC 案例的产量单位保持源站 `ton`，不擅自换成公吨；措施金额为美元，不与模拟项目的人民币收益直接比较。
- 模拟 ERP/MES 能耗数据与 UCI 真实工厂数据必须分开分析。UCI 原始 15 分钟 `CO2(tCO2)` 字段应沿数据集原始定义使用，不直接套用模拟项目里的排放因子口径。
