# 阶段二：预测与智能归因

## 目标与原则

在 2σ、产量基线和 CUSUM 之外增加预测能力，但不以单一深度学习模型替代统计检测。所有模型使用相同特征口径、相同滚动时间窗口和相同指标比较；归因摘要必须能追溯到指标字典、SQL 结果和异常证据，禁止补写证据之外的原因。

## 实验矩阵

| 模型 | 角色 | 输入 | 状态 |
|---|---|---|---|
| 季节性朴素基线 | 最低可接受基准 | 同车间 7 日滞后 | 已落地 |
| LightGBM | 非线性表格基准 | 统一特征表 | 已落地 |
| LSTM | 序列模型对照 | 固定历史窗口 | 待实现 |
| Transformer | 长依赖对照 | 固定历史窗口 | 待实现 |
| 2σ / 产量基线 / CUSUM | 可解释检测基准 | 现有 SQL 结果 | 保留 |

滚动验证必须按时间前后切分，禁止随机划分。每个折只允许使用训练截止日以前的数据拟合；统一报告 MAE、RMSE、样本量与预测明细。`train_days`、`test_days` 都是连续自然日，特征构建和切折两处都会拒绝日期缺口。

告警提前量定义为“模型首次有效预警时间到经确认事件 `onset_time` 的时间差”。真值来源只能是维护记录、操作员确认或模拟场景预先写入的 ground truth；Q22、Q24、2σ、CUSUM 和预测残差都是待比较的检测器，不能互相充当真值。契约位于 `ml/schemas/incident_label.schema.json`。当前数据没有合格标签，所以指标输出 `null` 和 `unavailable_no_verified_incident_labels`，而不是编造提前量。

## 统一特征

`ml/feature_pipeline.py` 从清洗后的能耗和产量明细生成“车间×日”特征：产量、气温、周末/月度周期、能源价格指数、生产/低负荷/停产状态占比、目标滞后与滚动均值。当前数据没有生产计划、天气预报或预测时点设备快照，因此实际产量、实际温度、价格指数与设备状态统一滞后一天；当天只使用事先可知的日历特征。所有目标历史统计同样先 `shift(1)` 再滚动，防止把当天实绩泄漏给当天预测。

Airflow 在 `clean_data` 后执行 `build_features → run_validation → verify_ml_artifacts`；验证任务检查特征业务键与本批清洗输入完全一致，并从预测明细复算 MAE/RMSE。GitHub Actions 执行同一路径并上传预测证据工件，避免“本地文件存在但已经过期”。

在 731 个连续自然日上，季节基线与 LightGBM 使用完全相同的 365 日起始训练期、30 日测试窗口和 30 日步长，每个模型各得到 2,928 条预测。季节基线 MAE/RMSE 为 0.7513/1.3144 tce，LightGBM 为 0.4848/0.8027 tce，分别降低约 35.5%/38.9%。这些数值由 `ml/model_benchmark.py` 生成，并由 `tools/verify_ml_artifacts.py` 从逐条预测重新计算；不能用该结果推断告警提前量。

## 智能归因证据边界

后续 RAG 助手仅允许检索三类来源：

1. `docs/指标字典.md` 中的口径与定义；
2. `output/Q*.csv` 中的 SQL 结果；
3. 2σ、产量基线、CUSUM 与预测残差产生的异常证据。

每个归因结论必须返回来源文件、记录键/指标名和证据值。没有证据时输出“证据不足”，不得根据行业常识虚构设备故障、人员操作或生产计划原因。提示词、检索结果、引用和最终摘要需要作为一次分析运行的审计记录保存。

首版归因输出契约位于 `ml/schemas/attribution_result.schema.json`：每条 claim 至少包含一个 citation，且来源类型只能是指标字典、SQL 结果或异常证据。
